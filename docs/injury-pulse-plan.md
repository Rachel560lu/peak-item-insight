# 伤势恢复与手持物品预览：开发与验收计划

状态：用户于 2026-09-08 批准实施。0.1.9 已实现并完成自动化与 Unity 合成自检；真实局内伤势/手持验收待完成。下文保留设计依据，最新结果见 `recovery-held-019.md`。

## 1. 目标与当前基线

- 当前版本保留为 0.1.8，测试配置为 `PeakItemInsight-Test`。
- 用户已确认饥饿预览成功。截图中半边椰子显示饥饿 30 → 20，黄色饥饿段中对应恢复量的部分变绿；这作为本次扩展的回归基线，不代表所有饥饿边界情况已实机验收。
- 本计划把“健康值”解释为原生 HUD 右侧心碎图标对应的 **伤势 Injury**，不是当前跑动消耗的精力，也不是所有负面状态的合称。
- 目标：悬停或手持已识别为降低 Injury 的物品时，让原生橙色伤势段中“使用后将消除的部分”在原本橙色与健康绿色间平滑切换。失去全部有效预览来源后回到原样。
- 2026-09-08 新增需求：当前拿在手里的物品也能触发预览，适用于饥饿、伤势及已有的文字效果/说明，不要求准星持续对准物品。

## 2. 本版范围

包含：

- 伤势完整恢复、部分恢复、零恢复、无伤势四种情况。
- 复用已工作的 1.4 秒黄绿往返节奏；伤势对应橙绿往返。
- 保持饥饿预览行为不变；若某物品确实同时减少饥饿和伤势，两段独立预览并同步节奏。
- 增加当前手持物品来源；与准星悬停来源统一选择、计算、展示，不叠加两件物品的效果。
- 目标切换、暂停、关闭预览、HUD 消失、场景切换时清理预览。
- 构建、诊断日志、自动化测试与隔离部署检查。

不包含：

- 毒素、孢子、炎热等其他状态的闪烁扩展。
- 新增伤势、毒素等不利效果的 HUD 占用预览。
- 新增额外精力图形、重新设计说明面板、补全所有道具效果。
- 自动使用治疗物品、主动制造受伤、改变存档/人物状态以通过测试。

其他效果继续保留现有文字提示。绿色恢复提示不代表物品没有副作用。

## 3. 交互规则

以下数值为测试用例，不宣称某一具体物品固定治疗这些数值：

| 当前 Injury | 预测使用后 Injury | 原生伤势段表现 |
|---|---|---|
| 5% | 0% | 整段橙色 ↔ 绿色 |
| 20% | 15% | 靠近健康精力条一侧的 25% 区域闪烁，剩余 75% 保持橙色 |
| 5% | 5% | 不闪烁 |
| 0% | 0% | 不创建可见闪烁区域 |
| 5% | 10% | 不画绿色恢复；仍显示现有不利效果文字 |

- 恢复量 = `max(0, Before − After)`。
- 覆盖比例 = `clamp(恢复量 / Before, 0, 1)`；Before 为 0 或数据非法时关闭覆盖。
- 当治疗量超过已有伤势时，使用现有预测层截断后的 After，最多覆盖整个伤势段。
- 伤势条保持当前位置、宽度、原生纹理/边框和图标。只对覆盖层做显隐，不移动其他状态条、不提前缩短伤势段。
- 原生状态条存在最小显示宽度：比例应用于该伤势段的实际可见区域，而不是以整条精力宽度直接猜像素。
- 原色阶段必须露出原本的橙色；绿色阶段沿用健康填充颜色。没有恢复的部分一直保持原色。
- 仅饥饿减少的食物不触发伤势预览；仅治疗伤势的物品不触发饥饿预览。

### 悬停与手持的优先级

已实施的默认冲突处理：**有效悬停目标优先，否则回退到当前手持物品**。

| 情况 | 显示内容 |
|---|---|
| 空手，准星对准物品 A | A 的预览，标记“准星” |
| 手持物品 B，准星看地面/天空/无有效物品 | B 的预览，标记“手持” |
| 手持 B，准星对准物品 A | 只显示 A，不叠加 B |
| 从 A 移开准星，手里仍拿着 B | 清除 A 后切换回 B，不误判为残留 |
| 切换手持 B → C，且无有效悬停目标 | 清除 B 后显示 C |
| 空手且无悬停目标 | 隐藏面板和所有恢复覆盖层 |

- “手持”只指当前装备在手的物品实例，不遍历背包或预览所有快捷栏物品。
- 若悬停目标是工具、没有状态恢复，或效果尚未支持，仍保留该悬停目标的说明/未知提示，不偷偷显示手中食品的绿色恢复。优先级不以“是否有绿色可画”为依据。
- 同一时刻，说明面板和 HUD 必须指向同一件物品；面板增加“准星/手持”来源标识及物品名。
- 手里拿着食物时看地面仍有预览属于预期；只有没有任何有效来源时才完全消失。
- 同一个有效手持目标保持稳定预览，不因每帧检查或视角移动反复重置闪烁周期。
- 使用动作开始后，暂时隐藏该手持来源的预览，避免实际治疗与预测重复表达；取消/完成后重新读取状态与剩余次数。最后一口或耗尽后不保留旧效果。另一个独立悬停目标仍按其自身状态处理。
- 空手、放下、销毁、卸下物品后不再把它当作手持目标。暂停、旁观、角色不存在和禁用时统一隐藏。

## 4. 实现步骤

### A0. 统一预览来源

- 当前代码已经在 `WorldPreviewTrace` 中只读观察 `Character.localCharacter.data.currentItem` 和 `consuming`；可作为手持来源接入点。实现前验证装备、切换、使用中的生命周期语义，不能只根据模型是否显示来判断手持。
- 保留 `HoverResolver`；新增手持解析器与单一目标选择层，输出 `PreviewTarget = { source, itemInstance, identity }`。先选择一件物品，再进入现有预测与渲染链路。
- 区分世界 FakeItem 标识和其 prefab、真实手持 Item 实例；缓存键加入来源和实例标识，不能只凭 itemID 共用使用次数、烹饪状态或预测结果。
- 每帧先判断暂停/禁用/角色有效性，再选择悬停或手持目标。来源/实例切换立即清除旧预览，对新目标沿用约 0.12 秒稳定延迟；同一目标状态变化重新计算，但不每帧重置动画。
- 缓存失效条件包括人物状态、当前物品、烹饪状态、剩余次数及使用状态；场景/角色/HUD 更换需要重新绑定。
- 手持物品不会因没有地面射线命中而走旧版的无悬停直接隐藏路径。预测器仍只读，不调用拾取/使用操作，不把“拿着”当成自动触发 OnHeld 效果的依据。

### A. 复用预测，明确按状态分流

- 沿用悬停检测、物品实例读取和 `ItemPreview.Statuses`。
- 精确选取 `STATUSTYPE.Injury` 的 Before/After，不用物品中文名判断是否治疗，也不按所有状态的净和推导伤势恢复。
- 先检查现有治疗动作识别路径，确认使用次数、启用状态和触发条件被尊重；若预测本身缺失，不伪造绿色效果。

### B. 独立覆盖层，共用绘制算法

- 保留已验收的饥饿比例计算、遮罩、坐标跟随和透明度算法。
- 为 Injury 创建单独的覆盖层实例，禁止饥饿和伤势共用一个可变 RectTransform。
- 从 `StaminaBar.afflictions` 按 `afflictionType == Injury` 找到原生段，再获取其实际填充 Image，排除图标和本 Mod 创建的覆盖层。
- 两段使用同一有效预览目标的起始时间，实现同步的 1.4 秒平滑周期；状态数值更新不应每帧重置动画。
- 找不到某一种原生段时，只关闭对应预览并记录诊断，不影响另一种已绑定的预览。
- 原生填充因当前精力耗尽而隐藏时仍可读取其健康颜色，不能因此错误关闭有恢复量的伤势提示。

### C. 生命周期与隔离

- 悬停/手持来源或物品切换时，立即隐藏旧目标的两个覆盖层；移开准星后若手持有效物品则回退预览该物品，否则隐藏。
- 新目标只包含一种恢复时，主动关闭另一种旧覆盖层，避免残留。
- 保持现有暂停、禁用、旁观状态的隐藏入口；场景对象销毁后重新绑定新 HUD。
- 只创建/销毁本 Mod 自己的 UI；不修改原生 Image 的颜色、尺寸、激活状态、共享材质或人物数值。

### D. 诊断与版本

- 保留 `HUNGER_PULSE`，新增 `INJURY_PULSE` 与 `INJURY_PULSE_UNBOUND`。
- 每条有效诊断包括进程/物品标识、来源（Hover/Held）、实例标识、Before/After、覆盖比例、原生宽度、覆盖宽度、可见性及透明度；目标切换诊断说明回退/隐藏原因。
- 日志按状态限频，不因为饥饿先输出而吞掉同一物品的伤势诊断。
- 更新日志读取脚本，支持两个恢复状态；区别活动进程与已退出的零线程残留记录，不能读取旧版本日志冒充本次成功。
- 实施版为 0.1.9；只替换隔离测试配置 DLL，保留旧版本备份。

## 5. 自动验证矩阵

### 离线检查

- 现有 40 项检查继续通过。
- 伤势整段、部分、过量治疗截断、无伤势、无效果、增加伤势、非法输入。
- 来源选择测试：空手、仅悬停、仅手持、悬停优先、工具/未知目标不穿透回退、悬停退出回到手持、切换/丢弃/使用耗尽。特别验证同类型不同实例不会混用缓存。
- 编译产物确认运行入口确实调用两个状态的预览，隐藏入口能清理两者；旧的净精力方块不会重新启用。
- 继续检查生产代码没有调用使用物品、修改状态或网络交互等禁止的方法。

### Unity 内合成 UI 自检

- 用独立黄色饥饿段、橙色伤势段和健康绿色填充运行真正的生产渲染代码。
- 测试完整治疗和 20 → 15 的部分治疗；断言伤势覆盖宽度为原生显示宽度的 25%。
- 检查原色、全绿、原色三个时间点，及位置移动、缩放、不同健康侧方向。
- 测试仅饥饿、仅伤势、两者同时恢复、两者都没有效果的状态分流。
- 从双恢复目标切换到单恢复目标：另一层必须消失；无悬停且空手时两层都隐藏。
- 通过真实生产目标选择层测试悬停 A → 手持 B → 空手，以及手持食物 → 手持工具；面板来源与 HUD 效果始终一致，旧覆盖层没有残留。
- 测试原生 HUD 隐藏、覆盖层销毁/重新绑定，以及原生颜色和尺寸不变。
- 自动截图核验实际绘制和裁剪，不只看 RectTransform 数值。

合成自检不能替代真实物品/原生伤势纹理绑定和真实治疗结果的验收。

## 6. 部署前检查与实机验收

请用户进局前必须完成：

1. 离线测试和 Unity 合成自检通过，无未解释异常。
2. 正常退出游戏后备份当前测试 DLL 与存档；只部署到 `PeakItemInsight-Test`。
3. 构建、分发、测试配置三份 DLL 哈希一致。
4. 隔离启动的新 PID 日志包含正确版本/MVID、FIRST_FRAME 与持续心跳。

真实局内验收顺序：

1. 在已有伤势时，悬停已识别的绷带等治疗物品 3～5 秒，不立即使用：确认橙色段原位橙绿切换，饥饿段不受影响。
2. 空手时移开准星：恢复原色，无覆盖残留。
3. 有条件时验证部分治疗：仅对应比例闪烁。以日志中实际 Before/After 为准，不为了测试主动制造伤势。
4. 回归已成功的饥饿食物场景；确认饥饿预览未被破坏。
5. 用户愿意实际使用治疗物品时，再对比治疗前后数值；否则明确把数值兑现验证留为待验收。
6. 拿起食品或治疗物品，看地面保持 3～5 秒：仍显示标注“手持”的预览。仅验证自己拿在手里的实例，不要求额外使用。
7. 手持 B 时准星对准 A：只预览 A；看回地面切换回 B。切换到工具或空手，原恢复预览正确消失。
8. 有条件时验证多次使用、取消使用和最后一次耗尽后的重新计算；未执行的用例明确标为待验收。

只有伤势的真实画面验收通过后，才报告该功能实机完成。若绑定失败或显示错位，先收集本次日志，不要求用户反复重启猜测。
